# 高斯场景转角修复记录

2026-10-31。用户反馈转角异常，未提供具体症状或复现步骤。本次确认并修复下述两个问题，尚不能认定它们就是该反馈的全部原因。

## 复现与修复

1. **小幅转动未更新高斯遮挡顺序。** 内置 Gaussian Splats 排序器默认在相机移动不足 1 个场景单位、方向变化不足约 8° 时跳过排序。用两个前后深度会交叉的高斯点，将相机从 −0.1° 调到 +0.1°，旧代码没有派发新排序，仍使用上一机位的顺序；输出预览则会强制排序，两条路径可能表现不一致。现在只要相机矩阵改变就请求排序；工作线程忙时合并连续编辑，完成后处理最新机位。同一机位不会持续派发任务。
2. **长距离拖动使方位角超出控件范围。** 从 0° 向右拖动 3000 像素，旧取余公式得到 −330°，而控件范围为 −180° 至 180°。改用欧几里得取模，结果为等价的 30°；左右拖动、多圈拖动均保持规范范围。

修复位于 `web/editor/splat.mjs` 和 `web/editor/scene.mjs`，未修改第三方库、重建模型或保存的原始机位定义。编辑器入口及模块缓存标记更新为 `20261031splat`。

## 已完成验证

- 修改前，新增的小角度排序、连续旋转补排序、长距离拖动三项回归均失败；修改后通过。
- `tests/splat-sort.test.mjs` 调用实际内置排序派发器，使用可控制完成时机的工作线程替身验证深度顺序、忙碌时合并、导出相机返回和静止后无额外排序。它不是实际 WebGL 像素测试。
- 全部 JavaScript 单元测试 **303/303 通过**，包括相机、焦距、预览导出、拖动撤销、批量和图库相关测试。
- 读取本机 12 份不同高斯重建参数，检查 9 个方位角 × 5 个俯仰角 × 3 个焦距 × 3 个画幅，共 **4,860 组**。相机矩阵均有限，工作台框内坐标与输出投影的最大归一化误差约 **1.01×10⁻⁷**。这是 CPU 几何检查，不是实际渲染、模型出图或浏览器交互测试。

本次尚未完成浏览器目视验收。应重点实测：连续微调角度后停手、从实时工作台切换预览再返回、较大横向拖动，以及带原图裁切的竖图/横图。不能用上述自动测试代替用户原始问题的完整复现。
