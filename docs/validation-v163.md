# 1.6.3 修复与实测

- **重建来源误判：**实际 TripoSplat 任务读取 1536×864 RGBA 原图，输出来源记录指向重导出的 RGB PNG。两图 RGB 像素最大差异为 0，文件哈希不同。前端现在根据该任务的 LoadImage 与输出连线确认来源，将原始素材记录绑定到重建结果。旧完成缓存在任务历史仍存在时可恢复；历史已清空或模型资产已移除时需要重新重建。
- **机位可改变：**复用实际 PLY，调至方位 58.24°、俯仰 6.2°，浏览器生成真实 PNG，8192 快照接口应用成功、回读一致。修复不限制角度、缩放或平移，也没有关闭不同来源图的检查。
- **素材操作：**未展开的卡片直接显示替换、删除。替换保留 ID、名称、用途、目标、排序；删除首图时清除失效首图选择。替换、删除、撤销、重做、保存与重新打开经过真实浏览器检查，320 / 390 / 1440 像素下按钮未溢出。连线素材需在上游更换，或先明确使用已保存版本。
- **提示词重复：**Studio 输出接回 `studio-plus-input` 时，原实现把相同文字拼接了两次；现在相同输入去重，独立补充文字继续追加，`input-full` 保留原文。实际 Turbo6 运行回执确认自动人物说明只出现一次。
- **多人用途核对：**实测四人场景、引导与七张参考共八图均进入编码器。新增角色仅使用身份用途时，服装与画风不在复制要求内。卡片已增加说明，可从同一素材分别绑定身份、服装、配饰和风格。用途属于文字指令，人物身份、站位与局部画风仍须检查实际生成结果。

验证：248 项 JavaScript 测试、118 项 Python 测试、13 种窗口尺寸、12 项浏览器交互场景。另复用了实际重建任务并保存调整机位后的输出，进行四人八图 Turbo6 实测。用户参考图、场景快照与测试工作流仅留在本地，不包含于此发布。
